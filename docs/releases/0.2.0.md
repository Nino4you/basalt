# Basalt 0.2.0 — second preview

Almost everything has changed since the first preview (0.1.0-preview.1): graph, canvas, dockable
panels, live preview in the editor, Obsidian-style settings, much broader plugin compatibility
and a noticeably faster start. **Still a development preview, not a complete replacement for
Obsidian.**

This is the first release with **production signatures**: the Android APK/AAB is signed with the
release key, and the Linux packages and `SHA256SUMS` are signed with OpenPGP. The fingerprints are
listed in the README and in `SIGNING.txt`.

## New

### Workspace

- **Graph view** in Obsidian style, global and local, with group colors; the local graph adapts
  to small panels and keeps its settings behind a gear icon.
- **Canvas** (JSON Canvas 1.0, `.canvas`): files from other apps are preserved losslessly.
- **Dockable panels** like in VS Code: reorder with drag & drop, close and reopen them.
- **Split views**: canvases and attachments are shown in every editor group.
- **Settings** redesigned in Obsidian style, with separate category pages on phones; reworked
  controls.

### Editing and reading

- **Live preview**: KaTeX math, Mermaid diagrams and tables appear right in the editor. Tables
  stay visible while editing and only the active cell shows Markdown; undo reverts a cell edit in
  one step.
- Callouts, tables and Mermaid look the same in the editor as in the reading view; math, tasks,
  table alignment and canvas fitting fixed in the reading view.
- Hover previews for internal links, templates with title and date placeholders, toggling tasks
  from the keyboard.
- Rename files (also with F2) without open tabs losing their state.
- Search: exclude terms, step through results with the keyboard and open them in a new tab.

### Your notes, safer and better connected

- **File recovery:** earlier versions of a note or canvas and deleted files can be compared
  with the current content and restored, from the command palette or "Version history" in the
  file menu. Nothing is overwritten: the replaced content is backed up itself, and a deleted
  file whose name is taken comes back as a copy.
- **Links follow renames and moves:** wiki links, embeds, Markdown links and canvas cards that
  pointed to a renamed or moved file are rewritten, also when a plugin renames it. Each changed
  file is backed up first; Settings → Files and links turns it off.
- **Unlinked mentions** in the backlinks panel, turned into a link with one click.
- **Aliases** from the frontmatter in link completion (`[[Note|Alias]]`), the quick switcher
  and unlinked mentions.
- Completion for `[[Note#Heading]]` and `[[Note#^block]]`.
- **Daily notes** with their own folder, Moment.js-style date format and template, and
  commands for the previous and next one; a template folder of your choice.
- **Hotkeys** can be changed, removed and reset in the settings.
- The status bar counts the words of the selection; commands to move or delete the current
  file.
- While you type, the app backs up its own autosaved content at most every five minutes per
  note instead of on every save, so the history stays readable. Content the app did not write
  itself is still always backed up first. (Android keeps backing up every save for now.)

### Android and touch

- Formatting toolbar for touch editing; phones in landscape keep the phone layout, tablets get
  larger touch targets.
- The app no longer sits under the navigation bar and the keyboard.
- Creating files in SAF folders fixed.

### Plugins

- **Plugin catalog:** Settings → Community plugins browses the Obsidian community catalog
  (checked plugins marked, the rest labelled untested) and installs, updates and uninstalls
  plugins from their GitHub releases. Your own plugins install from any GitHub repository or
  from local files. Every install asks first and never enables the plugin by itself.

- Plugin settings are stored as `data.json` in the vault (`Basalt/Plugins/<id>/`) and travel
  with it.
- Many additional Obsidian APIs: menu and command registries, editor commands, editor
  suggestions, hover links, tag counts, built-in helper functions and a POSIX path module.
- Obsidian path forms are accepted; `.obsidian` configuration lands in `Basalt/Config`.
- Plugins can load their own files (for example OCR models) through narrowly scoped resource
  URLs.
- **Iconize:** file menu, file tree view and persistent icons in the explorer.
- **Excalidraw 2.29.2:** editing and SVG/PNG export verified in a browser test.
- Plugins that cannot be restored at startup are shown instead of being skipped silently.

### Speed

- The first note appears before plugins are loaded; plugin data is read in batches.
- After saving, only the saved note is read again instead of the whole vault.
- Incremental note graph, local graph via breadth-first search, drawing within a frame budget.
- Android/SAF: folders are no longer listed again on every read.
- Smaller app packages: icons and KaTeX are loaded on demand.

## Installation

- **Linux x86_64:** install the `.deb` with your package manager or make the AppImage
  executable. Built and startup-tested on Ubuntu 24.04.
- **Android (ARM64, ARMv7, x86_64):** install `Basalt_0.2.0_android-universal.apk`.
- **Verify:** see "Verifying downloads" in `docs/release-signing.md`.

> **Upgrading from the 0.1.0 preview on Android:** The old preview is signed with the
> development key, so Android does not install 0.2.0 as an update over it. Export your notes from
> the app's private vault first, uninstall the preview and then install 0.2.0. Future releases
> install as regular updates.

## Known limitations

- Sync, pen/OCR and spreadsheet plugins have not yet been verified end to end on real devices;
  plugin tests mostly run in a browser harness.
- No auto-update, no signed APT repository, no Play Store upload.
- Plugin code runs unsandboxed in the main WebView. Only enable trusted bundles.
- Android SAF providers do not guarantee atomic file replacement.
- File recovery covers notes and canvases; backups of attachments still have to be restored by
  hand, and backups are not cleaned up automatically yet.
- Emulator and browser tests do not replace tests on real Android devices.
