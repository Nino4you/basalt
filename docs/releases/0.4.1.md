# Basalt 0.4.1 — plugin hotfix

A small fix release for the plugin compatibility layer. **Still a development preview, not a
complete replacement for Obsidian.**

## Fixed

- **Plugins that update themselves reload correctly:** `app.plugins.enablePlugin`,
  `disablePlugin`, their `...AndSave` variants and `getPlugin` were missing, so a plugin that
  installed its own update failed with "disablePlugin is not a function" and only ran the new
  version after a restart. A reload now re-reads the plugin's files, and plugin views and code
  blocks are rebuilt around it. A plugin that fails to load reports the error instead of
  silently returning `false`.
- **Readable errors from plugin network requests:** when `requestUrl` failed before reaching
  the server (for example an invalid URL or a connection error), plugins showed "undefined"
  instead of the reason. They now get a regular `Error` with the message.

## Installation

- **Linux and Windows with 0.4.0:** Settings → General → check for updates → "Install and
  restart".
- **Linux x86_64 (new install):** install the `.deb` with your package manager or make the
  AppImage executable.
- **Windows x64 (new install):** run `Basalt_0.4.1_x64-setup.exe`. The installer is not
  code-signed yet, so SmartScreen asks once ("More info" → "Run anyway"); check it against
  `SHA256SUMS` first.
- **Android (ARM64, x86_64):** install `Basalt_0.4.1_android-universal.apk` as an update over
  0.4.0.
- **Verify:** see "Verifying downloads" in `docs/release-signing.md`.
