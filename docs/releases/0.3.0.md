# Basalt 0.3.0 — third preview

A large step towards everyday use: properties, footnotes, folding, search and replace across the
vault, file recovery, links that follow renames, attachments by paste and drop, sync conflict
help, themes, print and HTML export, and a catalog for community plugins. **Still a development
preview, not a complete replacement for Obsidian.**

## New

### Editing

- **Properties:** frontmatter shows as editable fields (text, lists, numbers, checkboxes, dates)
  in live preview; comments and key order in the YAML stay. "Add property" (Ctrl+;).
- **Footnotes** (`[^1]`, `^[inline]`) in the reading view with links back and forth, marked in
  the editor; "Insert footnote".
- **Folding** of headings, list items and blocks from the margin, with fold commands.
- **Search and replace** across the vault: one term (with `path:`/`tag:` filters), optionally
  case-sensitive, in one file or all after a confirmation; every changed note is backed up.
- **Attachments:** paste or drop pictures and files into a note; they go to the attachment
  folder from the settings (`/`, `./`, `./subfolder` or a vault folder) and are linked.
- **Print and PDF** (Linux) and **export as HTML**, a single file with styles and images.
- **Vim key bindings** as an option, loaded only when switched on.
- Completion for `[[Note#Heading]]` and `[[Note#^block]]`.
- The status bar counts the words of the selection; commands to move or delete the current
  file.

### Your notes, safer and better connected

- **File recovery:** earlier versions of a note or canvas and deleted files can be compared
  with the current content and restored, from the command palette or "Version history" in the
  file menu. Nothing is overwritten: the replaced content is backed up itself, and a deleted
  file whose name is taken comes back as a copy.
- **Links follow renames and moves:** wiki links, embeds, Markdown links and canvas cards that
  pointed to a renamed or moved file are rewritten, also when a plugin renames it. Each changed
  file is backed up first; Settings → Files and links turns it off.
- **Unlinked mentions** in the backlinks panel, turned into a link with one click.
- **Aliases** from the frontmatter in link completion (`[[Note|Alias]]`), the quick switcher
  and unlinked mentions.
- **Daily notes** with their own folder, Moment.js-style date format and template, and
  commands for the previous and next one; a template folder of your choice.
- While you type, the app backs up its own autosaved content at most every five minutes per
  note instead of on every save, so the history stays readable. Content the app did not write
  itself is still always backed up first. (Android keeps backing up every save for now.)
- **Backup cleanup:** backups can be removed automatically after 7 to 365 days (off by default,
  so nothing is deleted after the update); Settings → Files and links shows their size and
  empties the trash on request.
- **Sync helpers:** conflict copies from Syncthing, Nextcloud and Dropbox and notes with Git
  merge markers are pointed out and can be compared and resolved; on Linux the vault reloads
  when the window gets focus. See `docs/sync.md`.

### Look and settings

- **Themes and CSS snippets** from `Basalt/Config/themes` and `Basalt/Config/snippets`, chosen
  in Settings → Appearance (stored in `appearance.json` like in Obsidian).
- **Hotkeys** can be changed, removed and reset in the settings.
- **English user interface** by default, German selectable in the settings.
- **Update check** (off by default): Settings → General asks GitHub for a newer release and
  links to it; nothing is installed automatically.

### Plugins

- **Plugin catalog:** Settings → Community plugins browses the Obsidian community catalog
  (checked plugins marked, the rest labelled untested) and installs, updates and uninstalls
  plugins from their GitHub releases. Your own plugins install from any GitHub repository or
  from local files. Every install asks first and never enables the plugin by itself.

## Changed

- **No ARMv7 build any more:** the Android APK/AAB contains ARM64 and x86_64. Phones that can
  only run 32-bit ARM apps get no further updates.

## Installation

- **Linux x86_64:** install the `.deb` with your package manager or make the AppImage
  executable. Built and startup-tested on Ubuntu 24.04.
- **Android (ARM64, x86_64):** install `Basalt_0.3.0_android-universal.apk`. It installs as an
  update over 0.2.0 (same signing key).
- **Verify:** see "Verifying downloads" in `docs/release-signing.md`.

## Known limitations

- Sync, pen/OCR and spreadsheet plugins have not yet been verified end to end on real devices;
  plugin tests mostly run in a browser harness.
- No automatic installation of updates, no signed APT repository, not in F-Droid or Google
  Play yet (the listing is prepared in `fastlane/`, see `docs/distribution.md`).
- Plugin code runs unsandboxed in the main WebView. Only enable trusted bundles.
- Android SAF providers do not guarantee atomic file replacement.
- File recovery covers notes and canvases; backups of attachments still have to be restored by
  hand.
- Printing is not available on Android (the WebView has no print dialog); export as HTML and
  print from a browser instead.
- Emulator and browser tests do not replace tests on real Android devices.
